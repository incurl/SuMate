# SuMate · 东坡嘴替

> 让苏轼的嘴，替你说那句说不出口的话。

SuMate（东坡嘴替）不是一个诗词搜索框，而是一台**逐层挖掘的精神矿机**。
用户不写关键词，而是通过五个维度的树形选择，一层层逼近自己此刻的状态——
说不出口的愁、解不开的结、刚好的清闲——最终从三千余首苏轼词、两千余个
最小匹配单元里，挖出**最懂你此刻的那一句**。

---

## 一、它做了什么

| 能力 | 实现 |
|---|---|
| 全语料精标 | 钦定四库全书《东坡词》321 首、65 词牌、2230 句、376 联 |
| 多维情感分级 | 正面 / 中性哲思 / 低回疗愈 三维 + 六种东坡专属气质，强度分四级 |
| 哲学立场层 | 11 个立场，各带前提与影子；按用户处境检验前提是否成立 |
| 五维标签树 | 143 个节点、4 层嵌套，五个根入口，全部节点可达 |
| 逐层下钻 | 每一步实时刷新剩余候选数，面包屑可回溯、可重来 |
| 任意层预览 | 不到叶子也能查看当前组合命中的全部诗句 |
| 收敛匹配 | 语义契合 + 情绪共鸣 + 情境一致 + 东坡气质 + 哲学前提 五轴打分，输出 Top-1 + 2~3 备选 + 解释 + 确信度 |
| 结构化输出 | 全部标注为 JSON 友好结构，字段预留计数统计位 |
| 无名之句 | 没有命中任何概念的 171 句，单独成架（`/#shelf`），按成因分组呈现 |

## 三、语料从哪来

`东坡词.txt` 是**钦定四库全书**本《东坡词》：它给出权威的词牌、词题
（含小序）与正文，但用的是繁体与异体字（収、囘、防……），且没有断句。

`chinese-poetry` 的 `宋词/ci.db`（MIT）提供了同一批词的现代断句与标点。

`tools/build_corpus.py` 把两者合并：

1. 解析四库正文——识别 `词牌【词题】`、`又【词题】`、`集句`、`原缺/阙文`
   等各种体例，并处理词题内嵌在正文行中的情况；
2. 与 `ci.db` 逐首对齐，用 `difflib` 的 opcode 做字符级映射，从而把标点
   **投影**到四库原文上（四库用字保持不动）；
3. 归一化为简体，并修正常见的四库异体字；
4. 产出 `data/dongpo_corpus.json`。

```bash
python3 tools/build_corpus.py && ./tools/sync_corpus.sh
```

## 四、标注是怎么来的

三层知识叠加：

1. **概念词典**（`internal/curated/knowledge.go`）——45 个语义概念，把古典意象
   翻译成机器可读的单位。每个概念带表层义、深层意境、哲理内涵、态度、
   极性、情绪、东坡气质、标签与触发关键词。
2. **历史层**（`internal/corpus/history.go`）——从词题推导年代、地点与人生阶段。
   干支年（丙辰中秋）通过六十甲子循环反查；名篇另有一份「词牌 + 标志性字句」
   的考据表，补足四库词题没有写下的年份与地名。
3. **人工校订**（`internal/curated/overrides.go`）——《水调歌头》《定风波》
   等重名篇的逐句精读，覆盖自动推导给出的文字。

标注引擎（`internal/annotate`）把它们合成为每句的完整档案：表层义、深层意境、
哲理内涵、态度、极性、分级情绪、六种东坡气质、适用人群、情绪阈值、场景边界、
疗愈属性，以及五个维度上的标签。

## 五、哲学层：安慰是有前提的

情绪与气质回答的是「怎么感觉」「怎么扛」，哲学层回答的是「**怎么活**」。

东坡最著名的句子几乎都带着一个未写出的条件：

- 「此心安处是吾乡」的前提是**已无别处可去**——对一个还走得动的人，它是不走的理由；
- 「拣尽寒枝不肯栖」的前提是**已经冷过**——它不是建议，是报告；
- 「莫听穿林打叶声」的前提是**后面还有路要走**。

所以产品不把安慰无条件交出去。每个立场带四样东西：**主张**、**前提**、
**影子**（前提不成立时它变成什么）、**何以说得出**（东坡写这句时经历过什么）。

系统只根据用户**实际选中的标签**检验前提，结果分四档：

| 档 | 含义 |
|---|---|
| `held` 正合 | 前提成立，这一句是站在他位置上说的 |
| `strained` 只合一半 | 勉强成立，只剩一半意思 |
| `unknown` 待定 | 说得不够，还看不出 |
| `failed` 不合 | 前提不成立，这一句未必是给他的 |

`failed` 的句子被**降权但仍然展示**，并附上它自己的影子——例如
「舍不得再走」在处境已变时会变成「不必再走的理由」。

**匹配分高 ≠ 那一句对。** 分高只说明它符合标签；「是不是那一句」要看与次优的
差距，以及用户说得多具体。两套指标分开报。

产品自己也要交代立场：它的前提是什么、失效时会变成什么、**找不到时怎么办**
（说找不到，而不是硬凑一句像样的）。

## 六、匹配算法

刻意**不做关键词匹配**。五轴加权：

| 轴 | 权重 | 含义 |
|---|---|---|
| 语义契合 | 0.30 | 意境与用户此刻状态的接近程度 |
| 情绪共鸣 | 0.28 | 分级情绪画像与所选心境标签的吻合度 |
| 情境一致 | 0.24 | 处境、地点、时令、人际标签的重叠度 |
| 东坡气质 | 0.18 | 是否携带东坡式的豁达与超越 |
| 哲学前提 | +0.06 | 这一句的前提是否对读者成立 |

另加一档产品偏置：优先带有疗愈、旷达、超越意味的句子——这是「东坡嘴替」
与普通情感词典的区别。

## 七、无名之句：系统够不着的地方也有门

2,604 句里有 171 句没有被任何概念命中。它们拿不到标签，因此**进不了五个维度，
也从不出现于匹配结果**——在界面上等于不存在。

现在它们有了一个去处：树面板底部的「另有 171 句，未能命名」，
也可以直接用 `/#shelf` 打开。

这不是一个纪念柜，也不是错误清单，而是一面**诊断面**：它按成因分组，
并且诚实地说明多数并不是「深刻到无法命名」，而是别的：

| 组 | 句数 | 含义 |
|---|---:|---|
| 长度如常，而未有名 | 17 | 这是标注的边界，不是文本的边界 |
| 偏短，意象未成形 | 98 | 五到七字，短到构不成可命名的意象 |
| 太短，无以名之 | 56 | 《如梦令》的「但洗。但洗。」就在这里 |

含全语料仅见一次的字的句子会带一个「疑讹」标记——那是**提示不是判决**：
四库传本多异体，「鹅」「禹」「尹」都很清楚，不构成讹字。

> 一个把盲区藏在深处的系统，和一个把盲区摆在门口的系统，
> 后者更值得信任。

## 八、标注是怎么被验出来的

格式正确 ≠ 数据正确——这是 `../oblique` 工程用两次数据事故换来的教训，
本项目继承这条纪律。

**两层校验**（`tools/lint_corpus.py`）：

- **格式层**（5 项）：底本完整性、括号配对、无嵌套、无半角引号、类型白名单；
- **领域层**（3 项）：**词牌↔字数**、句读归属、最小单元非空。

其中「词牌↔字数」是苏词的领域约束，等价于楹联的「上下联等长」。
它一上来就抓出了三处真实缺陷：校语混进词句、缺文被静默删除、`has_text`
标志与实际文本不符。

**底本分层**：四库正文里的 `【…】` 一律不是词句——或是缺文（只计数，不补字），
或是集句所引的作者，或是异文，或是校语。四者**按顺序剥**，顺序反了集句就
永远识别不出来。

**词表纪律**：触发词分强弱。具体词组（「拣尽寒枝」）是强证据；单字（「风」「月」）
只出现在三成以上语料里，不得单独成立——弱证据仍贡献标签，但不进入「主要概念」。

**规律库**：`docs/RULES_标注规律库.md` 记录 12 条规律，每条都来自一次真实错误，
包括记录「我自己犯过的错」的反向规律。

## 九、目录结构

```
data/dongpo_corpus.json        合并后的语料（唯一事实源，嵌入 Go 二进制）
docs/SPEC_苏词标注规范.md      标注规范
docs/RULES_标注规律库.md       规律库
internal/
  model/       领域类型（JSON 友好）
  philosophy/  前提检验：这一句此刻是不是在对你说
  corpus/      语料加载、最小单元切分、历史推导
  curated/     概念词典、情绪表、哲学立场、情态映射、人工校订
  annotate/    标注引擎
  tagtree/     五维标签树与过滤/计数
  engine/      五轴匹配算法（含哲学前提检验）
  service/     对前端的唯一入口
cmd/dump/      审阅标注质量的开发工具
frontend/      Wails v3 + TypeScript 前端
tools/         语料构建、校验、词表审计与全流程脚本
```
