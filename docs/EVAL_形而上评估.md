# SuMate（东坡嘴替）形而上评估

> 对这个工具的**存在论**追问：它究竟是什么？它对「意义」的假设是什么？
> 它许诺了什么？它是否配得上自己的许诺？
>
> 本文基于对代码与语料的实际测量，不基于设计意图的复述。

---

## 一、它是什么

**它是一台把状态翻译成句子的机器。**

剥离一切修辞：用户通过树形选择说出自己的处境，系统从 2,604 个句单元中
挑出分值最高的一个，并解释为什么。

这个定义里有三个词值得逐一追问：**状态**、**翻译**、**句子**。

---

## 二、它对「意义」的假设

### 2.1 意义是可标注的

系统把「月与相思」「酒中真趣」「苦中作乐」当作可以挂在句子上的属性。
这假设了：**意义是句子的内在属性**，而不是读者与句子之间关系的效果。

这个假设有相当的经验支持——「但愿人长久」确实自带某种语义场；
但它有一个代价：**一旦标注完成，意义就被冻结了**。系统不知道同一个句子
对不同读者意味着什么。

### 2.2 意义是可分解的

45 个概念、25 种情绪、6 种气质、11 个立场——全部是**正交的、有限的、可枚举的**。

这是整个工程最漂亮也最可疑的一步。它让「无法言说的状态」变得可计算，
代价是：**凡是不在这 45 个概念里的状态，就成了噪声**。

实测：2,604 句中 171 句（6.6%）**不命中任何概念**，只能被检索、无法被解读。
而那些句子恰恰是「人间有味是清欢」这类最不整齐的句子。

### 2.3 意义是层级可分的

五维标签树断言：一个状态可以被拆进五个正交的抽屉。

实测这条断言**基本成立**——五根的覆盖是 2380/1497/1444/1868/2225，
没有一句落在所有维度之外，也没有一个节点是空的。树是一个**忠实的索引**
（每个节点的报数与实际含该标签的句子数完全一致，已逐项核对）。

这是整个项目最扎实的一块地基。

---

## 三、它许诺了什么

产品的许诺是：「让苏轼替你说那句说不出口的话」。

这句话有三层，每一层都要兑现：

| 层 | 许诺 | 是否兑现 |
|---|---|---|
| 1 | 找到**贴切**的一句 | 部分兑现 |
| 2 | 找到**此刻对**的一句 | 部分兑现（哲学层在做） |
| 3 | 找到**你**的那一句 | **基本未兑现** |

---

## 四、它没有兑现的部分

### 4.1 五个轴里有四个在决策处失效

这是最严重的一处，而且比「算错了」更麻烦：**它算对了，但饱和了。**

在全量候选上，各轴是有区分度的：

```
全量 2604 句：
  语义 : 标准差  3.72   取值 2 种
  情境 : 标准差 30.49   取值 2 种
  气质 : 标准差 27.12   取值 32 种
```

但**决策并不发生在这里**。决策发生在前几十名。而在前 50 名上：

```
前 50 名：
  语义 : 标准差 0.00   取值 1 种   ← 常数
  情境 : 标准差 0.00   取值 1 种   ← 常数
```

原因很直接：语义轴只检查「有没有概念」「哲学字段是否为空」，情境轴只检查
「带不带这个标签」。凡是能进前 50 的句子，这两件事**必然都成立**，于是两轴
在决策区退化为常数。占权重 0.30 与 0.24 的两轴，合计 **0.54 的权重在排序时
不产生任何差别**。

### 4.2 宽泛选择下，排序是同分下的任意

上一条的直接后果，而且是可以被证伪的。选 `mood.low`（宽泛）后看前 30 名：

```
   1. 暮云收尽溢清寒。                总分 82
   2. 此生此夜不长好明月明年何处看。          总分 82
   3. 暮云收尽溢清寒。银汉无声转玉盘。         总分 82
   ...
  前 30 名中与第 1 名同分者：30 句
```

**三十句同分。** 全部四个轴在前 50 名上都是常数，于是总分也成了常数，
排序由 `sort.SliceStable` 的稳定性决定——也就是**由底本文件里的先后顺序决定**。

验证：把语料倒序后重建引擎，同一个选择给出不同答案。

```
正序底本 → 暮云收尽溢清寒。
倒序底本 → 烂漫游玉辇东还。杏花风数里响鸣鞭。
```

这是整个项目最深的一处：**产品许诺「最贴合的那一句」，而在宽泛选择下
不存在「最贴合」——系统对该选哪一句是无差别的，它的无差别由一个与意义
无关的事实（文件顺序）解决。**

系统把一个任意的选择，呈现为一个有共鸣的选择。

这不是 bug，是**设计层面的沉默**：代码没有错，是「选」这个动作本身没有发生。

### 4.3 树深不影响结果

实测：

```
只选根节点   → 暮云收尽溢清寒。
选到第二层   → 暮云收尽溢清寒。   ← 与上一档相同
选到第三层   → 欲向佳人诉离恨…
```

选到第二层与只选根节点给出**同一个答案**。因为树过滤出的候选集是对的，
但引擎在候选集内部**并不再区分深度**——它只是再看一遍标签。

多维度也一样：加上「时令」后候选数仍是 2,604（引擎不按交集过滤），
答案不变。**树负责生成候选，但候选之间的取舍几乎不由树决定。**

### 4.4 自由文本几乎无效

用户唯一能用自己的话说出的东西，是那个输入框。实测：

```
「我想一个人待着」 → 暮云收尽溢清寒。
「我很累不想动」   → 暮云收尽溢清寒。
「思念远方的人」   → 暮云收尽溢清寒。
```

前五名**完全不变**。原因在 `descriptionScore`：它把描述与关键词**按单个汉字**
求交集。「我」「了」「想」这类字遍布关键词，所以几乎必然命中——
它测的是汉字重合，不是意义。

**这是整个产品里最严重的断裂**：用户被邀请用自然语言说出自己，
而系统几乎不听。

### 4.5 标注与标签之间存在裂缝

实测：选了 `mood.low.longing` 之后，**1,117 句（占全部候选的 43%）被情绪轴判 0 分**。

例句：「香生雾縠见纤柔。」「清香细细嚼梅须。」「流香涨腻满晴川。」

这些句子**确实带着「遥远想念」这个标签**（否则不会进入候选），
但它们的概念命中的是 `daily.food`、`serene.joy.quiet`，
于是 `mood.low.longing` 对应的情绪键根本不在它们的情绪表里。

**标签说它「想」，概念说它「香」——两者互相矛盾，而系统没有任何机制发现这一点。**

这是「概念」与「标签」两套平行词表没有对齐造成的系统性裂缝，
而不是个别错误。

## 五、它做对了的部分

### 5.1 底本分层

四库正文里的 `【…】` 一律不是词句：缺文只计数不补字，集句作者与异文
按顺序剥离，**校语绝不进词句**。

这条「只加标记，不改原文」的纪律，让整个语料可以被逐字复核。
实测：三首集句被正确识别（吴融、郑谷、杜牧……），三处缺文被如实计数，
没有一处校语混入。

### 5.2 哲学层

这是全项目最有思想密度的一处，也是**唯一真正在区分句子的轴**。

它做对了一件关键的事：**承认安慰有前提**。

> 「此心安处是吾乡」的前提是**已无别处可去**。
> 对一个还走得动的人，它是不走的理由。

系统实测两种读者给出不同答案：

- 无助的读者 → 「有些事不是你不努力」**正合**
- 有希望的读者 → 上面那句**不合**，并附上它自己的影子：
  *「不是你的错」也可以用来掩盖「你没试」*

这是真正的差异：**同一句词，落在不同的人身上，是两回事**——系统知道这一点，
并且说出来。

### 5.3 确信度与诚实

「匹配分高」与「是不是那一句」被拆成两套指标，并按**与次优的差距**和
**用户说得多具体**计算。校准后：空选择 25 → 宽泛 38 → 精确 64。

产品知道自己不确定，并说明为什么不确定、要怎样才能更准。
一份凑得很近但前提不成立的安慰，比一句诚实的「这里没有」更有害——
系统知道这一点，并据此行事。

### 5.4 产品的自我定位

`internal/curated/product.go` 让工具交代自己的前提、失效方式，
以及**找不到时怎么办**。

一个承诺「替你说话」的工具，愿意公开自己的失效模式——这在产品史上罕见。

## 六、形而上学小结

### 6.1 这个工具是什么

**它不是「理解你的工具」，而是一台极其勤奋的检索器，装备了一套精心设计的
元数据，以及一个在关键时刻后退的排序器。**

它做对了检索器的本分：语料干净、结构忠实、计数准确、解释完整、诚实标注
不确定性。但在「选」这个动作上，它有相当一部分时候**并没有在选**。

### 6.2 一个关于「无差别」的悖论

产品许诺的是「**最贴合的那一句**」（the single most resonant verse）。

「最」这个字预设了一个**全序**：任意两句之间，总有一句更贴合。
但实测表明，在宽泛选择下，前三十名的分数完全相等——系统对该选哪一句
**没有偏好**。

于是系统做了任何排序算法都会做的事：它保持了原顺序。
而原顺序是底本的文件顺序，与「贴合」毫无关系。

> **一个无差别的系统，输出一个差别的答案，而这个差别来自无关的事实。**
> 这不是它在撒谎，是「最贴合」这个词与它的实现之间，有一段它自己没有
> 察觉的距离。

### 6.3 承诺与兑现

| | 承诺 | 兑现 |
|---|---|---|
| 结构 | 逐层挖掘 | ✅ 树是真的，计数是真的（逐项核对） |
| 语义 | 懂你的意思 | ❌ 决策区标准差 0.00 |
| 选择 | 最贴合的一句 | ⚠️ 宽泛时 30 句同分，答案随文件顺序变 |
| 哲学 | 这一句此刻对你说 | ✅ 全项目唯一起作用的区分轴 |
| 声音 | 替你开口 | ❌ 你的话（自由文本）几乎不被听 |

**最尖锐的结论**：这个项目对「苏轼」的处理是成功的，对「用户」的处理是失败的。
它极好地匹配了**标签**，而标签是系统的，不是用户的。

### 6.4 一个元层面的自指

产品的核心承诺是「把**你说不出**的话交给**东坡**说」。
但当前实现里，能被交出去的，是**系统能命名**的那些状态——
也就是已经在标签树里的那些。

**系统的能力边界，恰好就是它能理解的范围。**
用户真正的「说不出口」，恰恰是他**无法自己命名**的状态——
那正是标签树之外的部分，也是 171 句无概念句子的所在。

产品哲学层诚实地承认了这件事（「你的处境还没有被说到足够具体」），
但承认不等于解决。

### 6.5 若要名副其实，需要什么

按投入产出排序：

1. **让自由文本真正起作用**（把字符重合换成语义匹配）。
   这是唯一一条「用户自己的话」的通道，现在是断的。
2. **在决策区引入区分**（当前两轴标准差 0.00）。
   哪怕只是按概念的丰富程度、按句子的具体性给一个连续的权重，
   也能让前三十名不再同分。
3. **打破同分时的任意性**。
   同分时不应退回文件顺序；应当有显式的、可解释的破平规则
   （例如「更短者优先」——短句更像一句可以被说出的话）。
4. **对齐概念表与标签表**（43% 的矛盾）。
   两套词表必须由同一份定义派生。
5. **让树深影响排序**（当前第二层与根节点同答案）。

## 七、一句话

> SuMate 已经是一台很好的**索引**，还没有成为一台**翻译机**。
> 它能精确地告诉你「有 2,380 句写着低回与疗愈」，
> 但还没有能力说「你此刻这句话，我听懂了」——
> 而后者才是「嘴替」二字所许诺的。
>
> 更有意思的是它自己的态度：
> 哲学层、确信度、产品的自我定位，
> 全都在同一个方向上用力——诚实地标出「这一句什么时候不为你而说」。
>
> 一个诚实的工具知道自己可能在凑；
> 而一个**以为自己在选**的工具，会把它凑到的那一句，说成是为你选的。
>
> 前者已经做到了。后者还没有。

## 八、这些结论怎么复核

本文不是评论，是可复算的断言。复核：

```bash
go run ./cmd/audit
```

它会重新算出：各轴在全量与前 50 名上的标准差、标签与情绪的矛盾比例、
自由文本是否改变排序、树深是否改变答案、以及**倒序底本是否改变答案**。

> 这与 `tools/lint_corpus.py` 是同一条纪律：
> **不能复算的断言，不是断言。**
